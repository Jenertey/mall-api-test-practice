# Mall 接口自动化测试练习：面试讲解稿

## 30 秒介绍

这是我为开源 Mall 系统独立完成的接口测试练习工程。商城本身不是我开发的，我负责测试框架、接口封装、数据工厂、数据库校验、用例设计、报告和 CI。

## 哪些是原创

- 基于 requests 的 Mall 管理端 API 客户端和 Bearer Token 会话管理
- 保证唯一 SKU 的商品测试数据工厂
- 分页、结果码和商品字段的契约断言
- JSON Schema 离线契约校验和敏感字段日志脱敏
- MySQL 商品与 SKU 库存一致性检查
- 22 条测试场景矩阵和分层 pytest 配置
- Allure 报告、GitHub Actions 和 Issue 模板

## 最难的点

主要难点是商品创建接口不会直接返回新商品 id，所以测试不能依赖创建响应，而是通过唯一 productSn 反查商品列表，拿到 id 后再做读取、断言和清理。

## 必答题

- 为什么把写操作测试单独标记为 mutating？
- 登录失败时 Mall 返回 HTTP 200 但业务 code 非 200，框架如何处理？
- 如何保证测试商品可清理、SKU 不重复？
- 数据库检查和接口断言分别覆盖什么风险？
- 为什么要同时保留离线契约测试和真实接口测试？

## 边界说明

被测系统来自开源社区，不能声称是自己开发的。正确的表达是：我基于该系统独立设计并实现了测试工程，负责测试架构、代码、用例、文档和持续集成。
